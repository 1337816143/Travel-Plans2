# 迭代路线

## Phase 0：平台底座（当前）

- monorepo、领域模型、供应商接口、规划引擎和 CI；
- 旧项目迁移矩阵；
- Web/小程序功能一致性契约；
- 数据来源、许可证和社区反馈边界。

## Phase 1：青岛端到端样板

- Next.js Web 与 Taro 小程序外壳；
- PostgreSQL/PostGIS、API 服务和本地开发环境；
- 高德搜索、路线、天气适配器；
- 将旧项目地点、餐饮、路线和预设转换为新数据；
- 地图选点、图标、编号、分组、备注和自定义路线；
- 保留打印、分享、主题、愿望清单和多设备检查。

## Phase 2：强自定义规划

- 多日拖拽、锁定项和局部重算；
- 营业/预约/交通/天气冲突检查；
- 自定义线型、粗细、箭头和方向；
- 批量管理地点、图层、城市、日期和成员；
- 撤销、版本历史、草稿和多端同步。

## Phase 3：动态事实与反馈

- 官方公告和动态事实更新；
- 用户反馈、证据、反垃圾和审核；
- 聚合信号与“来自旅行者反馈”展示；
- 冲突、过期、解决和回滚流程。

## Phase 4：全球与跨城

- 接入全球开放地点、天气和交通数据；
- 第二个国内城市、第一个海外城市；
- 多城市/多国家路线、时区、换城日和跨境注意事项；
- 住宿区域优化和完整住宿方案。

## Phase 5：规模化内容生产

- 以区县为最小攻略单元；
- 城市、省州、片区/流域、国家和跨国模板自动组合；
- 编辑后台、来源审核、任务队列和质量评分；
- 成本、配额、缓存、降级和供应商切换。

每个阶段必须同时通过 Web 与小程序功能一致性验收；未通过前不进入下一阶段的大规模数据填充。
