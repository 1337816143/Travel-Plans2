# 数据源策略（2026-07-31）

原则：优先采用官方开放数据和允许持久化的来源；第三方搜索结果不能默认当作本平台永久数据库。每个适配器必须记录许可证、署名、缓存、再分发、商用和配额限制。

| 来源 | 适合能力 | 初始定位 | 关键限制 |
|---|---|---|---|
| 高德开放平台 | 国内地图、POI 搜索、输入提示、路线、天气 | 国内首选交互供应商 | 个人认证存在月配额；国际 POI/路线需申请海外权限且属于高级或付费服务；搜索不是全量数据源 |
| OpenStreetMap 数据 | 全球道路、设施和基础 POI | 全球开放底图与种子数据 | ODbL 署名和衍生数据库义务；生产环境应使用数据摘录、自建或合规托管服务 |
| OSM 公共 Nominatim | 少量用户触发的地理编码 | 仅开发/低流量备用 | 最大约 1 次/秒；禁止自动补全、系统性 POI 抓取和周期性批量地理编码 |
| OSM 公共瓦片 | 低流量在线地图 | 仅原型和低流量备用 | 必须署名与缓存；禁止批量下载和离线预取；无 SLA |
| Open-Meteo | 全球天气预报 | 原型与非商业阶段首选 | 免费接口面向非商业用途，约 10,000 次/日且无 SLA；商业上线需商业许可或自建 |
| Google Places | 全球高质量地点搜索和详情 | 按需付费增强源 | 必须启用结算，按 SKU 计费；字段和存储受条款约束，不作为免费基础库 |
| Mapbox Search Box | 全球交互搜索、POI、地址 | 海外搜索候选 | 按会话/请求计费；结果通常只允许临时使用，持久化需确认合同；默认约 10 请求/秒 |
| Wikidata / Wikipedia / Wikivoyage | 名称、简介、文化背景、官方链接 | 开放内容增量源 | 需遵守各自许可证和署名；不适合作为实时营业、票价或交通事实 |
| 各国/地方政府与景区官方渠道 | 开放时间、公告、票务、交通和安全 | 最高优先级事实源 | 格式不统一，需要逐源适配、快照和有效期管理 |
| GTFS / GTFS-Realtime | 公共交通线路和动态 | 有官方发布地区优先 | 许可证、更新频率和覆盖范围由发布机构决定 |
| 用户主动提交 | 临时关闭、入口变化、排队和现场体验 | 社区动态层 | 必须反垃圾、去利益相关、聚合展示，不能直接覆盖官方事实 |

## 大众点评、美团、抖音等平台

它们可以作为用户发现线索或经授权的合作来源，但目前不应把“抓取全站地点、作品、评论区和评论”设计成基础能力：

- 普通开放平台通常面向商家、自有账号、交易或经过审批的业务，不等于允许批量获取全站点评；
- 未授权抓取存在账号封禁、反爬、著作权、个人信息、商业秘密和平台条款风险；
- 也无法可靠识别商家小号、软广和伪装顾客，仅靠模型过滤不能解决合法性与证据完整性问题。

可行做法：

1. 接入正式开放 API、合作接口或购买授权数据；
2. 允许用户提交公开链接和现场反馈，但只保存必要的结构化摘要与来源；
3. 由编辑人员基于多个独立来源形成事实，不复制整段作品或评论；
4. 对所有外部内容保存采集时间、对象匹配证据、许可证和删除机制。

## 首批组合建议

- 国内：高德交互服务 + 官方渠道 + OSM/政府开放数据补充 + 用户反馈；
- 海外原型：OSM 数据 + 合规托管地图/搜索 + Open-Meteo + Wikidata/Wikivoyage + 官方旅游和交通数据；
- 商业化后：根据覆盖和成本采购 Google、Mapbox、HERE、Foursquare 或地区供应商，不让任何单一供应商成为平台主键。
