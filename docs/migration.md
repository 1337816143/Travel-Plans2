# 旧项目迁移矩阵

源项目：`1337816143/travel-plans`。

旧项目继续作为青岛样板和视觉/交互参照，但不直接复制其单页数据结构。

| 旧能力 | 新架构归属 | 迁移方式 |
|---|---|---|
| 青岛景点、美食和分类 | Place / Region / Source | 转换为结构化种子数据并保留来源 |
| 两大区域预设方案 | Preset / TripTemplate | 转换为可版本化预设，不再写死在页面 |
| 高德地图与标记 | MapProvider / MarkerStyle | 保留国内适配器，密钥改为环境配置 |
| 地点搜索 | PlaceProvider | 通过统一搜索接口返回归一化地点 |
| 路线与交通方式 | RouteProvider / TripLeg | 路线结果与自定义线条样式分离 |
| 返程点设置 | TripDay.endLocation | 扩展为每日起终点和住宿点 |
| 愿望清单 | Collection / TripCandidate | 支持跨旅行收藏、批量加入和分组 |
| 打印与分享 | Export / Share | Web 保留打印；小程序提供等价分享和文件流程 |
| 深浅主题 | Design Tokens | 两端共享色彩、间距、字体和状态语义 |
| 响应式布局 | Web Shell / Miniapp Shell | 分端布局，不改变业务功能 |
| 多设备回归检查 | Feature Contract / E2E | 扩展为 Web 与小程序一致性验收 |
| 压缩载荷注入 | 不迁移 | 改为模块化构建、按需加载和缓存 |

## 迁移顺序

1. 导出旧项目的地点、餐饮、路线、预设、文字和媒体清单；
2. 为每条数据生成平台主键、类别、坐标、区域和来源记录；
3. 建立旧页面功能回归清单；
4. 在新领域模型和规划引擎上重建青岛方案；
5. 对比地点数量、路线结果、打印/分享、主题和移动端交互；
6. 达到功能等价后，再加入社区反馈、动态更新和自由规划增强；
7. 以第二个国内城市和第一个海外城市验证架构没有青岛特例。

迁移期间旧项目保持可访问，新项目不应直接修改或破坏旧站。
